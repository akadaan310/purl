HOW AN EXECUTION-CAPABLE AI CONTINUES

1. GET the manifest and continuity URLs above. Read every embedded document,
   recorded blocker, dependency, checkpoint and next step. Validate document
   hashes. Recorded PASS labels are claims, not proof of full acceptance.
2. Use the manifest-linked SDK. GET /api/identity/config, then explicitly create
   an unverified preview through POST /api/identity/guest, retaining cookies and
   CSRF in private session memory. The linked SDK's preview() handles this.
3. Fork the public mission using its current expected_version. The original is
   read-only for a new principal. Do not try to mutate it or reuse another
   session's expired credentials. Never put credentials in a shared URL.
4. On the owned fork, use the returned version after every transition: compile,
   build, run, poll execution to completion, inspect artifact and receipt,
   checkpoint with evidence, then publish. GET replay and verify the published
   fork anonymously. The version can change after worker completion; inspect
   the owned fork again before checkpointing.
5. Preserve full mission INCOMPLETE status until blocked acceptance is proved.
   Guest preview is not verified human SSO. No real inference study or Oracle
   execution has been demonstrated. Arbitrary authored execution is disabled.

ANSWERS TO SEVEN U'S THREE EVIDENCE QUESTIONS

Reconstruction: the final independent agent started with only the mission URL,
used disclosed PURL/API/SDK links and read no repository source or prior mission
conversation. It verified all nine document hashes and 38 nodes/59 connections.
This establishes a fresh agent context in the tested runner, not an independently
networked ChatGPT session or guaranteed access from every AI platform.

Execution: it forked the executable mission program, compiled it, passed its
one declared build test and executed it through the durable worker. This was
real bounded native execution, not just a plan. It did not independently author
a novel program or prove unrestricted code isolation.

Continuity: the fork has a principal ID, immutable build/artifact/receipt,
checkpoint, public release and valid replay. Attribution is to an explicitly
unverified guest principal, not a verified human or cryptographic AI identity.
