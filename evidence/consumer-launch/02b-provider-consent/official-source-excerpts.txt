102: ## Configure your authorization path
103: 
104: Before registering clients, you need to configure where your authorization UI will live.
105: 
106: 1. In your project dashboard, navigate to **Authentication** > **OAuth Server**
107: 2. Set the **Authorization Path** (e.g., `/oauth/consent`)
108: 
109: Note: The authorization path is combined with your Site URL (configured in **Authentication** > **URL Configuration**) to create the full authorization endpoint URL.
110: 
111: Your authorization UI will be at the combined Site URL + Authorization Path. For example:
112: 
113: - Site URL: `https://example.com` (from **Authentication** > **URL Configuration**)
114: - Authorization Path: `/oauth/consent` (from **OAuth Server** settings)
115: - Your authorization UI: `https://example.com/oauth/consent`
116: 
117: When OAuth clients initiate the authorization flow, Supabase Auth will redirect users to this URL with an `authorization_id` query parameter. You'll use [Supabase JavaScript library OAuth methods](https://github.com/supabase/supabase-js/blob/master/packages/core/auth-js/src/GoTrueClient.ts#L2159-L2163) to handle the authorization:
118: 
119: - `supabase.auth.oauth.getAuthorizationDetails(authorization_id)` - Retrieve client and authorization details
120: - `supabase.auth.oauth.approveAuthorization(authorization_id)` - Approve the authorization request
121: - `supabase.auth.oauth.denyAuthorization(authorization_id)` - Deny the authorization request
122: 
123: ## Build your authorization UI
124: 
125: This is where you build the **frontend** for your authorization flow. When third-party apps initiate OAuth, users will be redirected to your authorization path (configured in the previous step) with an `authorization_id` query parameter.
126: 
127: Your authorization UI should:
128: 
129: 1. **Extract authorization\_id** - Get the `authorization_id` from the URL query parameters
130: 2. **Authenticate the user** - If not already signed in, redirect to your sign-in page (preserving the authorization\_id)
131: 3. **Retrieve authorization details** - Use `supabase.auth.oauth.getAuthorizationDetails(authorization_id)` to get client information including requested scopes
132: 4. **Display consent screen** - Show the user what app is requesting access and what scopes/permissions are being requested
133: 5. **Handle user decision** - Call either `approveAuthorization(authorization_id)` or `denyAuthorization(authorization_id)` based on user choice
134: 
135: The authorization details include a `scope` field (singular) containing a space-separated string of scopes requested by the client (e.g., `"openid email profile"`). You should display these scopes to the user so they understand what information will be shared.
136: 
137: Note: This is a **frontend implementation**. You're building the UI that displays the consent screen and handles user interactions. The actual OAuth token generation is handled by Supabase Auth after you call the approve/deny methods.
