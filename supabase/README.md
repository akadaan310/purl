# Supabase persistence

The service uses the Data API only from its server/worker, with a server-only
service-role credential. Browsers receive neither this credential nor direct
database access. `purl_read_document` is read-only; `purl_compare_and_swap` commits
the authoritative JSON document and normalized projections atomically.

Apply the ordered migrations through the Supabase CLI or SQL editor for a
dedicated project. Read [MIGRATIONS.md](../MIGRATIONS.md) first. No migration has
been applied to a hosted project by this repository task.
`config.toml` was generated by CLI 2.121.0 for optional local Supabase development;
automatic exposure of new tables and nonexistent SQL seed files are disabled.

`purl-artifacts` is private. Artifact helpers use SHA-256 keys, disallow upserts,
and verify downloaded bytes. The service-role key is an administrative trust
boundary: an operator holding it can bypass RLS and overwrite/delete objects.
Keep it exclusively in deployment secrets and use independent object backups.

The initial adapter is optimized for correctness and small deployments. Its
single authoritative document serializes writes and projects entities on every
commit. Indexed projections support operational queries, but the worker must
claim through CAS. Shard documents or add row-level command RPCs in a later
additive migration before claiming large-scale throughput.
