# Transition model: what survives each boundary

Data: `PROJECTION-MATRIX.json`, generated by `node scripts/projection-matrix.js`
from committed artifacts only. Loss is computed by substrateIO
(`substrate.info.conditional_entropy_pairs`, called from
`scripts/projection_matrix_measure.py`). Exact claims about the PARSE
boundaries are tested in `test/transition-model.test.js`. Labels follow
BRIDGE-NOMENCLATURE.md §0.

## 1. Object

A **transition** is a typed triple `(pre, operation, post)` recorded in a
**clock domain** (C-050) by the system that owns that domain. A **boundary**
is a map `f` from one system's representation to another's (C-048 edge
vocabulary). For a sample of pairs `(x, f(x))` two quantities are measured:

* **loss** `H(X | Y)`: the bits of the source that the output does not
  determine. `0` means the map is injective on the sample, so the source can be
  recovered.
* **spurious** `H(Y | X)`: the bits of the output that the source does not
  determine. `0` means the output is a function of the listed source fields. If
  it is above `0`, the output carries something the source lacks, such as an
  occurrence, a fresh id or a clock.

Where an identifier exists, each boundary is measured twice: **by-lookup** (the
projection keeps the id, so the source is recoverable by asking the owner) and
**content** (ids removed, keeping only what the projected document carries).
The gap between the two is what **references** carry. That is the source of the
bridge's losslessness: it holds addresses, not copies.

## 3. What each loss is (each diagnosed, not just measured)

* **B1: verb label only (DERIVED, tested).** 255 programs map to 120
  addresses. Every collision disappears once `PERTURB/b` is identified with
  `WRITE/flip/b` (test *B1 … loses exactly the verb label*). The address keeps
  the *operation*. The program keeps the *intent* (perturbation vs.
  construction). This intent is what the unified perturbation record
  (BRIDGE-NOMENCLATURE §3) needs, and the value address cannot carry it. So a
  perturbation must be recorded from the program, never re-derived from the
  address.
* **B2: spelling only (DERIVED, tested).** Canonicalization is idempotent and
  sends the four spellings of each program to one text. Its loss is
  `log2(4) ≈ 2`, minus the measured collisions among variants, and it consists
  of spelling only. `pathOf` writes the `/seurl` mount prefix and `parseMoves`
  reads the word after it. This is a convention every caller follows (5 call
  sites), and the first version of the test violated it. That was a test error,
  not a code defect.
* **B3: σ and π are not inverse (OBSERVED).** π (record → program) loses
  1.67 bits. σ (program → record, COMMIT) is not a function of the program:
  1.67 spurious bits, because each COMMIT mints a fresh record (id, author,
  version, parent). `π∘σ = id` on programs (loss 0 for B3b). `σ∘π ≠ id` on
  records. This is the expected asymmetry between a value and a record (K-11).
  The bridge is lossless on programs and **cannot be** lossless on records
  from programs. The *minimal loss boundary* is therefore B3a: what a record
  adds is exactly `{id, author session, parent, version}`, i.e. provenance and
  clock. Phase 7 tests this as the program model.
* **B4: extensional vs intensional identity (OBSERVED).** value_id collapses
  distinct addresses that denote the same value (0.60 bits). derivation_id
  does not collapse them (loss 0). This is the C-047 separation, measured.
* **B5: occurrence (OBSERVED; corrects an earlier note).** By-lookup, the
  transition determines the execution (loss 0). It is **not functional**
  (0.38 spurious bits) because 12 of the 57 distinct (address, value,
  environment, code, git) tuples were executed more than once, and each
  occurrence has its own `execution_hash`. Before the diagnosis, this was
  attributed to null `value_id`s. That attribution was wrong: the cause is the
  occurrence, and it shows that `execution_hash` ≠ `derivation_id` (C-047). By
  content, 1.62 bits are lost: which occurrence it was.
* **B6: ACSP event payload (OBSERVED).** The P-ACSP-EV-1 label sequence plus
  actor loses 0.73 of 3.58 bits of the 12 live-fixture events. With version
  and request hash it loses nothing.
* **B7: commits (OBSERVED).** One author and one operation. Without ids,
  **everything** is lost (5.25 of 5.25 bits). A development history is
  recoverable only by reference, which is why Phase 8 records iterations with
  commit and tree ids.

## 4. Result

INFERRED from B3–B7: across the measured boundaries **every lossless
crossing is lossless by reference** (an id that the owning system can
resolve). No measured content projection is lossless except the trivial
D3. So the bridge's losslessness is conditional on the owning systems staying
resolvable. This is the cold-reconstruction requirement, stated as a measured
dependency.

HYPOTHESIS (open): content loss at a boundary is bounded by the entropy of the
fields the target system *owns* (clock, occurrence, provenance). Supported by
B3, B5 and B7. Not yet tested on D1 (TOK), for which no corpus exists.
